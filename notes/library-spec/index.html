库定义规范

规则图像＋视频共用源资料：库定义规范（visual-prompt-system）

全库收录判定规范：变量取值原文一字不改、三层定义、六个变量库边界裁决、高频取值包上限（≤15 条/≤12KB）、命名与入库流程。

目录

零、原文不变式（最高优先级，覆盖本规范所有其他条款）零点五、写法规则库（方法层）一、三层定义变量库（取值层）模板库（结构层）示例库（成品层）二、六个变量库的边界三、与源库的分工三点五、媒介标注三点七、高频取值包四、命名规范五、入库流程六、双读者设计七、变量维度词汇表

本域三层结构与六个变量库的收录判定。任何条目入库前先过这里的判定问题；两可时按「你拿它做什么」裁决。

零、原文不变式（最高优先级，覆盖本规范所有其他条款）

  1. 变量库与模板高频包中的取值原文，任何整理、重构、优化、合并操作不得增删改一字。 唯一合法变更 = 志光亲述新经验时的"新增"，以及志光明确指示的逐字替换。
  2. AI 无改写权：任何 agent（含执行整理的 AI）发现原文有错、有重复、有更好的写法，只能记录到"待裁决"清单，不得直接修改。
  3. 本条与任何后续条款冲突时，以本条为准。违反本条的任何变更应整体回滚。

来源：2026-09-04 志光拍板。此条将其 Keep 分享玩法经验（变量定义表 + 映射取值 + 禁改写）的原文层定为系统宪法。

零点五、写法规则库（方法层）

解决「变量库都是固定描述、无法举一反三」的问题。三类生成规则：组合公式（A+B+C 骨架）、条件路由（如果X则Y查表）、参数化条目（{元素}/{场景}可替换槽位）。

  • 变量库 = 成品取值（零号条款管辖，一字不动）
  • 写法规则库 = 生成方法（可随经验迭代，不受零号约束）
  • 新提示词 = 写法规则(骨架) + 变量取值(填料)；生成的新条目经志光确认后回收入变量库

一、三层定义

变量库（取值层）

一句话：模板槽位的取值集合，查表、整条搬用、不改写。

判定问题：这条内容是组装前的素材吗——你拿它去填一个槽位，而不是直接投喂模型？

条目三种粒度（都合法）：

粒度 形态 例
原子条目 一条=一个完整描述 运镜"智能环绕跟踪，保持与主体恒定距离…"
链式条目 一组按顺序使用的原子条目，含节奏参数 哭情绪链：失焦→瞳孔→冷笑→崩溃（各含时长）
组合条目 多变量已按验证过的配对预组合，仍作单槽取值 打斗整合篇：动作+运镜+特效绑定的单次生成单元

不收录：完整交付级 prompt（→示例库）；组装方法与规则（→模板库）；带输入规格的工作流（→模板库·玩法包）。

模板库（结构层）

一句话：组装骨架——告诉你有哪些槽位、怎么填、什么组合会冲突。

标准构成：变量清单（指向变量库）+ 模板结构（{} 槽位）+ 组装规则 + 成品参照（指向示例库）。

两个子类：

子类 形态 例
场景模板 轻量骨架，槽位从变量库取值 单镜头运动 / 微表情特写 / 十五秒短剧…
玩法包 预制模板+输入规格+抽卡策略，整包采用不拆件 image2 各玩法 / 风格复刻

判定问题：它描述的是怎么组装，而不是具体取值内容吗？

示例库（成品层）

一句话：组装完成的交付级成品 prompt + 变量取值标注，用于直接复用或反向拆解。2026-09-04 起轻量示例内嵌于对应模板文件（模板结构节之后）；2026-09-16 起实测案例全文另存独立笔记（案例-*，模板内仅留索引）——防模板正文膨胀、保可读性。

判定问题：拿掉标注后，它是不是一份可以直接粘贴给模型的完整输入？

硬规则：入库必须带变量取值标注（用了哪些变量、各取什么值）——只贴原稿不标注的拒收。

二、六个变量库的边界

库 管什么 一句话判定 易混归属裁决
运镜 相机怎么动 "变的是相机/取景，还是主体？" 特效条目内已配对的运镜描述跟随特效走，不重复收录
动作 主体做什么（事件层） "这一拍发生了什么事件？" 打斗中的特效触发→特效库；人物调度（站位/走位）→动作库
表演 主体情绪如何外显（情绪层） "这条描述的是内在状态变化还是事件？" 动作=发生了什么；表演=什么情绪状态。哭/笑/眼神/呼吸/反应都在此
特效 非物理视觉效果 "描述的是能量/粒子/魔法表现吗？" 武器光效公式→特效库（随兵器查表）；施法手势=特效的触发动作子类，随特效收录不拆到动作库
场景 空间、环境、风格 "这条定义的是环境还是人？" 美学风格包（宋式/吉卜力）=场景库的整包风格预设
角色造型 角色外观定义 "这条定义角色长什么样？" 角色的情绪变化（表演）不收；五官/发型/服饰/视图类型/画风标签收

跨库不二收：同一条目只在一个库有正身；其他库需要时写"见 X 变量库·某节"，不复制。

三、与源库的分工

本域 ai-video 源库
定位 生产加速层：查表→组装→对照 来源与考证层：完整原稿、模型坑、逐组审计
内容 变量条目 + 骨架 + 标注示例 全量素材、方法、案例、教程原文
改动约束 变量取值原文一字不动 不动（保留）

教程原文（13 篇 PDF 存档）不参与本域任何提炼与引用。

三点五、媒介标注

每个文件 frontmatter 必含 medium: video|image|mixed；mixed 文件必须在目录表加「媒介」列或在节标题后缀（媒介：X）。检索规则：图像任务先过滤 medium=image/mixed，视频任务先过滤 video/mixed。

三点七、高频取值包

模板文件可内嵌高频取值包：该模板最常用的变量条目直接抄进文件，完整库仍是扩展层。

硬性上限（防爆规则）：

  1. 每个模板的高频取值包 ≤ 15 条目、≤ 12KB——超限即违反规范，拒绝入库；
  2. 只收「该模板 80% 任务会用」的条目：单一依赖库的模板取该库招牌档 5–10 条；多库依赖按使用频率加权分配条目额度；
  3. 内嵌条目必须逐字复制自变量库（含模型版本标注），不得改写、不得摘要；
  4. 内嵌条目与变量库同源同步：变量库条目修订时，同步检查所有内嵌该条目的模板（模板文件头 embedded_from: 字段登记来源库清单，供同步脚本检索）；
  5. 新增条目优先入变量库；只有当一个条目被 3 个以上模板内嵌时，才允许“晋升”为公共高频包（此时反过来把它从各模板抽出、回归单份维护）；
  6. 轻量示例原稿不受此限；实测案例全文另存独立笔记（案例-*），不占模板篇幅。

判断口诀：高频包是「顺手放几发子弹」，不是「把弹药库搬进枪里」。

四、命名规范

  • 变量库：X变量库（六类定名，不新增第六类以外的库）
  • 模板：模板-场景名 / 模板-玩法包名
  • 示例：示例库-系列名

五、入库流程

  1. 判层：组装前素材→变量库；组装方法→模板库；组装完成品→示例库；
  2. 判库：过第二节的判定问题与易混裁决；
  3. 变量条目逐字搬运并标模型版本（2.0/2.5）；示例必须补变量取值标注；
  4. 更新对应库的目录与域导航。

六、双读者设计

本域服务两类读者，检索方式不同：

读者 方式 依据
人 扫目录表→跳到节→复制条目 每库顶部「目录」表（节/条目数/内容摘要）
AI 两段式：读目录定位节→只加载命中节切片 目录+切片≈2–3KB/次，整库37–137KB；实测打斗任务 293KB→9KB

约束：

  • 目录表是 AI 的检索接口——新增节必须同步登记（节名/条目数/一句话摘要）；
  • 条目归属节要按「查表时的检索词」命名，不按来源文件名；
  • 大文件+目录切片是对"整条搬用语义完整"的保留，不预拆文件；单库超过 150KB 时再评估拆分。

七、变量维度词汇表

维度 含义 主要来源库
{人设} 角色外观与身份定义 角色造型
{场景} / {场景轮换} 空间环境 / 多镜场景切换序列 场景
{运镜} 相机运动描述 运镜
{动作} / {动作结构} 主体事件 / 动作编排 动作
{表演} / {情绪基调} 情绪外显 / 全片情绪定位 表演
{特效} 视觉效果描述 特效
{结构} 镜头/时间骨架（如五镜×3秒） 模板自带
{台词} / {歌词} 语音文本 自写
{卡点} 音乐事件锚点 自定+示例参照
{触发} / {反转机制} / {喜剧机制} 叙事转折装置 自写
{保持项} / {变化项} 一致性边界 角色造型·一致性
{画风} / {风格} 视觉风格标签 场景·风格包
{产品} / {卖点} 广告对象与主张 自写
{镜头路径} 一镜到底的穿行路线（含各段通过点） 运镜

{变身前后} 变身类转变的两端状态 角色造型·一致性
{知识对象} 科普/解说条目的主题实体 自写
{视觉策略} 知识呈现的画面手段(示意动画/字幕/复原) 自写
{对比} 画面对位关系(如外冷内暖) 场景
{世界规则} 一镜到底的穿行空间设定 自写

{转场} 镜头衔接装置(喷雾/遮挡/匹配) 自写
{产品呈现} 广告产品的展示方式 自写
