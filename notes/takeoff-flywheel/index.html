起飞点：有限正本＋无限生成＋有门槛回流

起飞点：有限正本 + 无限生成 + 有门槛回流

2026-09-04，志光亲述并定型："变量应该怎么从已验证的有限固定描述变成无限"——这个提问本身是视觉提示词系统从「素材收藏」跃迁为「生产系统」的临界点。志光原话："这是我们起飞的起点。"

核心机制（原文）

精确表述：不是"变成无限"，是"有限的正本 + 无限的生成 + 有门槛的回流"

有限（正本）              无限（生成端）                有限但增长（库存）

┌──────────────┐   ┌─────────────────────────┐   ┌──────────────────────────┐
│ 验证过的固定描述 │ → │ 写法规则（公式/路由/参数化）│ → │ 新条目 → 志光确认 → 回流入库 │
│ = 质量锚点     │   │ 组合空间 = 天文数字        │   │ = 库渐进长大，规则越来越准   │
└──────────────┘   └─────────────────────────┘   └──────────────────────────┘
        ↑____________________飞轮____________________↓

三个环节各自的职责

环节 是什么 不是什么
固定描述（正本） 训练数据、质量锚点——有限、验证过、一字不动（零号条款） 不是天花板，是地基
写法规则（模型） 组合公式保结构下限、条件路由定选档、参数化开变体空间 不是撒手生成——规则保证的是下限不是上限
志光确认（门禁） 质量判断——决定什么回流、什么丢弃 不是流程负担，是复利来源

缺任何一个环节都只是排列组合，不叫举一反三。

为什么这是"起飞点"

此前的系统状态：变量库=跑过的固定描述（能复用，不能举一反三）。瓶颈被志光一语点破后，补上写法规则库（组合公式 5 套 + 条件路由 5 张 + 参数化条目 3 类），系统从「检索复用」升级为「生成-验证-回流」的飞轮。

这是 Keep 分享玩法经验的显式命名：当年 16 个玩法不是一次设计出来的，是"素材+规则→生成→上线验证→好的留下来"滚出来的。当时是无意识的工作习惯，现在是命名的系统能力——习惯变制度，才可复制、可交接、可跨人执行。

飞轮运转动线

接到没做过的画面需求
→ 写法规则库选组合公式（定骨架）
→ 变量库/高频包取值（填料，验证过的质感）
→ 生成 → 好 → 志光点头 → 回流入库（正本+1，规则再验证）
→ 库越用越厚，规则越用越准

落地位置

  • 写法规则库：写法规则库（引言已固化本机制）
  • 宪法保障：库定义规范 §零（原文不变式）/ §零点五（写法规则库定位）
  • 本机制的定义权在志光——"无限"的方向与边界由需求方定义，不由工具定义。
