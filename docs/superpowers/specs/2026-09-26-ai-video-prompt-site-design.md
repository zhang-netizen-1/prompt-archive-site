# AI 图像与视频提示词案例网站设计方案

日期：2026-09-26
状态：已确认总体方向、影像资料馆视觉基调、画面优先的案例页与 A1 档案控件；实现细节见 `docs/视觉设计规范.md`

## 1. 目标与定位

面向公众提供可浏览、可检索、可复制的 AI 图像与视频提示词案例。一个可独立使用的案例对应一个永久页面。访客从案例主题与实际媒体理解用途，复制提示词原文，并可预览相关方法笔记。

图像和视频共用一个网站，分设“图像案例”“视频案例”两个入口。角色、场景、道具设定图可能是视频生成的前置资产，因此跨媒介案例用明确的“制作链路”相互关联。

本站以用户现有 Wiki 为内容来源。Wiki 原文和目录结构不因建站而修改；网站负责展示、关联和公开发布筛选。

## 2. 已核查的内容基础

- `wiki/library/ai-video/prompts/`：103 篇 Markdown；其中 56 篇文件名标为“用户实测提示词”。部分笔记明确写明未附平台、模型、成片或效果记录。
- 同一来源目录中有 19 篇以 `👀` 开头的图像资料，图像提示词、效果图、玩法包和图像模板混杂；是否构成独立案例须看是否有可单独使用的完整提示词，不按文件名批量认定。
- `wiki/library/visual-prompt-system/`：32 篇 Markdown，包含 6 个变量库、11 篇模板、4 篇独立案例及方法笔记。
- 该系统目录的 frontmatter 中有 5 篇标为 `medium: image`、6 篇标为 `medium: mixed`。混合笔记应按章节及用途归类，不强拆源文。
- 两个目录的 Markdown 共包含 152 处 Obsidian 媒体嵌入引用，本次在 Wiki 文件树中均可解析；此外还有大量普通 Markdown 图片引用。建站导出须同时处理两种语法，并逐条验证目标文件和媒体格式。
- “圣诞夜雪街追逐”和“白底变装旋转”的复现附件中各有实测成片与参考图。其他案例是否有可公开的成片，以逐条核查为准。
- 源内容混用 frontmatter、Markdown 表格、代码块、Obsidian `[[链接]]` 和 `![[媒体]]`；不能只按普通 Markdown 正文渲染。

## 3. 信息架构

| 页面 | 主要作用 | 核心内容 |
| --- | --- | --- |
| 首页 | 快速理解网站并进入内容 | 精选有成片案例、主题入口、搜索、近期新增 |
| 图像案例列表 | 按创作目标寻找图像案例 | 案例卡片、全文搜索、图像主题及结果图状态筛选 |
| 视频案例列表 | 按创作目标寻找视频案例 | 案例卡片、全文搜索、视频主题及成片状态筛选 |
| 案例详情 | 阅读媒体与复制提示词 | 主题、标签、媒体、提示词、证据与来源、关联笔记 |
| 合集页 | 汇总同一源文件中的多个案例 | 合集说明、案例目录、逐项跳转 |
| 笔记列表与阅读页 | 预览和阅读方法内容 | 摘要、目录、Markdown 正文、相关案例 |

主导航使用“图像案例”“视频案例”“方法笔记”；合集作为各类案例列表中的聚合入口。首页提供“看图像案例”“看视频案例”“学写法”三个任务入口，另有跨媒介的全站搜索。来源目录不直接充当公众导航分类。

## 4. 单案例页面

页面从上到下依次为：

1. **案例主题**：标题、一句话用途、已知时长和适用场景。原文未给出的时长或模型不推断。
2. **标签**：题材、情绪、镜头手法、媒介和已知模型版本。标签由独立的网站内容清单维护，避免改写源文件。
3. **图像或视频**：图像案例可展示已核对的结果图；视频案例有实测成片则原生播放。输入参考图与生成结果分区并分别标注。无媒体时显示文字排版封面，页面仍公开且可检索；不得用生成图暗示真实成片。
4. **提示词**：完整原文置于清晰的复制区。默认按钮为“复制全文”；多段或多镜案例可以附加分段定位与“复制本段”。复制文本取自原文，不混入站点摘要、标签、来源说明或按钮文字。
5. **来源与结果**：列出来源、已知平台或模型、用户反馈、媒体是否齐备和最近核查日期。视频区分“附成片”“用户称已测试但未附成片”；图区分“附结果图”“有参考图但未附结果图”；模板与方法示例单独标注。
6. **关联笔记**：展示相关模板、变量库或写法规则的简短预览，并可进入笔记阅读页。
7. **制作链路**：若图像结果用于另一个视频案例，或视频案例使用了本站独立图像案例生成的设定图，两页互相链接；普通参考图只在本页媒体区展示。

桌面端采用用户选定的“画面优先”单列布局：标题与标签之后先放大幅媒体及附件切换，再向下进入完整提示词。移动端按“主题 → 媒体 → 提示词 → 说明”线性阅读，复制按钮始终明确可见。视觉基调采用“影像资料馆”：深色导航与媒体承托区，浅色长文阅读区，暖铜色作为少量强调色。图标与交互采用 A1「克制的档案控件」；具体规范见 `docs/视觉设计规范.md`。

## 5. 内容映射与原文规则

- 一篇独立的用户实测提示词文件通常映射为一个案例页；`案例-*` 独立文件同理。
- 一篇文档包含多组可独立投喂的完整提示词时，每组映射为一个案例页，源文档另有合集页。拆页只在网站内容清单中记录节标题或原文范围，Wiki 原文不拆、不改。
- 图像案例也遵守“一组完整提示词一个页面”；只有占位符的骨架、变量取值和玩法说明进入模板或方法笔记，不冒充实测案例。
- 每个案例有明确的 `medium: image|video`。跨媒介文档可关联两类案例或作为共用笔记；单个案例同时含独立图像提示词和视频提示词时，按输出目标拆成两页。
- 表格中的单个取值、写法公式或没有完整提示词的段落，归入笔记/变量浏览，不自动当作完整案例。
- 提示词复制必须保留原有文字、标点、换行和原文中的特殊标记。展示层的摘要与结构化标签单独存储。
- 变量库与模板中内嵌的取值按 Wiki《库定义规范》的原文不变式处理。网站不自动改写、合并或去重这些取值。
- 同一案例在源库和生产系统中出现时，网站以一个主案例页展示，保留两个来源链接和各自用途说明；不拼接成新的“原文”。
- 内容 URL 使用稳定的编辑标识；修改标题、标签或排序时不改变已发布地址。

## 6. 搜索、筛选与媒体状态

搜索覆盖案例标题、人工摘要、标签和提示词正文。首版先选择图像或视频，再按主题、结果媒体状态、已知模型筛选；全站搜索可同时返回两类结果，并显示媒介标记。只显示确有数据的筛选值。

列表卡片优先使用已核对的图像结果或视频成片画面。参考图必须加标记。没有媒体的案例使用文字封面，并按媒介标“暂无结果图”或“暂无成片”。“已测试”来自用户声明时，页面显示“作者称已测试；本站未复测”，不推断生成效果。

## 7. 笔记预览

案例页的关联笔记卡展示标题、用途摘要和目录片段，点击后进入完整阅读页。阅读页支持标题目录、表格、代码块、图片/视频和可解析的 Wiki 内链。无法解析的内链在发布构建时报告；不得生成指向本机绝对路径的公开链接。

## 8. 内容导出与公开发布

内容流程为：只读扫描两个 Wiki 目录 → 读取网站内容清单 → 解析 Markdown 与媒体引用 → 生成站点数据和静态媒体文件 → 校验 → 发布。站点运行时不依赖访客访问本机 Wiki 路径。

第一批精选约 16–24 个案例，包含图像与视频两类：视频先覆盖有成片案例和无成片但可复制的稿件；图像先覆盖有结果图且提示词完整的案例，再补充文字案例。同时收录若干合集和 6–8 篇入门方法笔记。每一条公开内容都检查：原文完整、媒体可预览、来源可追溯、实测状态准确、素材适合公开展示。带影视作品名称、第三方视频或图像的条目逐项核对公开展示范围；源笔记已注明“仅供个人内部使用”或“未经许可禁止转载”的内容不自动进入公开候选。未完成核查的条目留在内容清单中，但不出现在公开站点。

## 9. 第一版验收标准

1. 每个已发布案例都有独立且稳定的 URL；合集中的完整案例可直接进入各自页面。
2. 图像结果、视频成片与输入参考图可正常预览且身份标注明确；无媒体案例仍能阅读和复制。
3. 复制全文所得文字与选定原文区域一致；多段复制不会带入其他段落或页面说明。
4. 案例的实测、模型和时长信息均有原文依据；缺失信息不补写。
5. 笔记的目录、表格、代码块、媒体和站内关联链接能在桌面与手机上阅读。
6. 发布构建能够报告缺失媒体、未解析链接、重复 URL 与未完成公开审核的条目。
7. 建站及内容导出不会改动两个 Wiki 源目录。
8. 图像与视频拥有各自入口，跨媒介案例的制作链路可双向访问，普通参考图不自动生成图像案例页。

## 10. 后续阶段

在第一版页面与内容规则验收后，再逐步扩充已核查案例、增加更细的检索维度，并依据真实使用情况调整首页精选和主题分类。
