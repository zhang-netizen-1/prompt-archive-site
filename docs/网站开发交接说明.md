日期：2026-09-26
用途：交给负责实现网站的 Agent。本文是规划交接，不代表已完成素材公开审核或授权发布。

## 一句话目标

建立面向公众的 AI 图像与视频提示词网站：**每个完整案例一个独立页面**，按“案例主题 → 标签 → 实际图像/视频 → 可复制的提示词原文 → 来源与实测说明 → 关联笔记”阅读。一个网站内分“图像案例”“视频案例”两个入口，共用搜索与方法笔记。没有生成结果的案例也可作为文字案例展示，但必须明确标注媒体状态。

完整方案：[设计方案](superpowers/specs/2026-09-26-ai-video-prompt-site-design.md)；视觉与交互定稿：[视觉设计规范](视觉设计规范.md)；执行拆解：[实施计划](superpowers/plans/2026-09-26-ai-video-prompt-site.md)。本说明用于快速交接，发生分歧时以用户已确认的设计方案及视觉规范为准。

```text

按创作目标浏览：人物设定 / 场景与道具 / 微表情 / 短剧 / 打斗 / 图生视频
最近整理的案例与方法笔记
```

### 案例列表

```text
页面标题 + 搜索框
图像与视频各有列表；全站搜索可同时搜两类
筛选：主题 / 有无结果媒体 / 已知模型
案例卡网格：真实结果图、成片画面或文字封面；标题、标签、媒介与媒体状态

```

### 单案例页

```text
面包屑 / 主题标题 / 一句话用途 / 标签

提示词原文区：复制全文；多段案例可增加复制本段
来源与结果：事实状态、已知模型、时长、用户反馈边界
关联笔记：模板、变量库、写法规则的预览卡
制作链路：相关的图像或视频案例（确有独立提示词时）

```

### 笔记阅读页

```text
标题 / 用途摘要 / 目录

关联案例
```

已确认视觉方向：采用 A「影像资料馆」。首页和媒体区使用深色底承托真实图像与视频；长提示词与方法笔记使用浅色阅读区，提高中文长文可读性。案例详情采用方案 1「画面优先」：标题与标签之后先展示大幅媒体及附件，再展示完整提示词，不采用桌面端画面与提示词并列布局。图标与交互采用 A1「克制的档案控件」：细线图标配文字、下划线媒体标签、就地复制反馈。没有结果媒体的卡片使用排版与主题色，不制造类似真实生成结果的封面。具体色值、排版、响应式和交互状态见[视觉设计规范](视觉设计规范.md)；实现时以真实浏览器截图检查桌面和手机端。

## 内容规则与验收重点

1. 每个完整案例有稳定、独立的网址；合集只是聚合入口。
2. 视频的“作者称已测试但未附成片”与“有可预览实测成片”明确区分；图像的“输入参考图”与“生成结果图”明确区分。
3. “复制全文”只复制提示词原文；中文标点、换行、台词和原文特殊标记不变。
4. 未知模型、平台、效果和时长不补写。标题中的影视作品名称不自动等同于官方合作或原片素材。
5. 笔记中的 Wiki 链接、图片、视频、表格和代码块可预览；缺失媒体与未解析链接在构建报告中可见。
6. 公开构建仅包含通过人工公开审核的案例与媒体；内部使用限定或转载受限的图像资料不能自动发布。本机开发预览可以包含待审核候选。
7. 实现过程中不修改 Wiki 原文。部署、域名绑定和公开发布不在本次开发交接的自动执行范围内。
