# AI 图像与视频提示词网站｜视觉与交互规范

| 项目 | 决策 |
| --- | --- |

| 案例详情 | 方案 1「画面优先」：主题与标签 → 大幅媒体与附件 → 完整提示词 → 来源与状态 → 关联笔记及制作链路 |

| 信息架构 | 同一网站内分“图像案例”“视频案例”入口，共用搜索和“方法笔记”；每个完整案例一个页面 |

草图中的 `FRAME / 档案` 是暂用页眉字样，**不代表网站名称已确定**。实现时可先作为占位，正式名称需用户另行决定。草图中的雪夜画面是源资料的**输入参考图**，不是生成结果；正式页面必须按真实媒体身份标注。

## 2. 设计原则

1. 先让访客看清案例，再让访客复制原文。影像是内容主角，界面控件保持安静。
2. 媒体身份比装饰重要。生成结果、实测成片、输入参考图和无媒体状态在文字上明确区分，不能只靠颜色或图标。
3. 提示词是可复用的正文。使用完整原文、保留段落和换行；视觉层不改变复制内容。
4. 笔记是阅读内容。长段中文、目录、表格与代码块优先考虑可读性，避免把笔记做成窄小弹窗。
5. 首页可有影像氛围，列表和阅读页以快速识别与查找为先；不要在每页重复大幅装饰性主视觉。

## 3. 色彩与排版

以下数值是首版实现基准，实际浏览器检查时可在不改变整体方向的前提下微调。

| 用途 | 色值 | 用法 |
| --- | --- | --- |
| 深色背景 | `#15191D` | 页眉、首页主视觉、媒体空白区域 |
| 深色控件 | `#253136` | 主要按钮、已选媒介标签 |
| 暖白页面 | `#F2EEE6` | 案例页和列表页背景 |
| 纯白阅读面 | `#FFFFFF` | 提示词与笔记正文容器 |
| 主文字 | `#253034` | 标题、正文 |
| 次级文字 | `#626C69` | 描述、辅助信息；在暖白背景上保留足够对比 |
| 暖铜强调 | `#D2A16A` | 首页少量强调、线条、焦点装饰；不用于浅底上的小号正文 |
| 浅底文字链接 | `#815B37` | 小号文本链接及“阅读全文”等动作 |
| 成功文字 | `#496F5D` | 复制成功反馈，辅以勾选图标和文字 |
| 分隔线 | `#DED8CD` | 阅读区边界、卡片描边 |

字体优先采用系统中文无衬线栈：`-apple-system, BlinkMacSystemFont, "PingFang SC", "Microsoft YaHei", sans-serif`。不依赖远程字体服务。正文默认 `16px / 1.7`；提示词正文 `15–16px / 1.75`，保留换行。页面主标题桌面端约 `40–48px`，手机端约 `29–34px`；区块标题约 `23–28px`。摘要与媒体说明不小于 `14px`。英文编号和眉题可用小号大写，但不承担唯一信息。

内容容器桌面端最大约 `1200px`；单案例主要阅读区约 `900–960px`；长笔记正文约 `720–800px`。页边距桌面端 `32–48px`，手机端 `16–20px`。间距基于 `4/8/12/16/24/32/48/64px` 的节奏。卡片和媒体圆角约 `6–8px`；避免大面积渐变、玻璃拟态和重阴影。

## 4. 页面结构

### 首页

- 深色页眉连接图像、视频、方法笔记和全站搜索。
- 影像主视觉传达定位，但主行动应直接进入“看图像案例”“看视频案例”“学写法”。
- 首页下半部转入暖白内容区，展示已核对的精选案例、按创作目标浏览和近期笔记。
- 首页媒体卡必须有“图像案例 / 视频案例”和“生成结果 / 参考图 / 暂无成片”等文字状态；不能以参考图冒充成果。

### 案例列表

- 图像和视频各有清楚的入口与页面标题。全站搜索的结果同时显示媒介标签。
- 桌面端优先三列卡片，宽度不足时两列、再转一列。卡片媒体区采用一致的视觉框架；图片可适度裁切作缩略图，但详情页展示完整画幅。
- 卡片信息顺序：媒体或文字封面 → 媒介/结果状态 → 标题 → 一句话用途或主题 → 少量标签。首屏不要堆满模型、时长、来源等次级信息。
- 筛选包含主题、结果媒体状态、已知模型；无结果时说明当前条件，并提供“清除筛选”。筛选值仅从真实内容产生。

### 单案例页

1. 面包屑、主题标题、一句话用途与标签。
2. 大幅媒体区：有生成结果或实测成片时默认展示结果；参考图和人物设定作为附件切换。若只有参考图，明确显示“参考图，未附生成结果/成片”。无媒体时使用文字状态块。
3. 完整提示词：阅读容器置于媒体之后，顶部固定呈现“复制全文”按钮；多镜头内容可提供段落锚点和“复制本段”。正文默认完整展示，不用截断或折叠隐藏大部分原文。
4. 来源与事实状态：源资料、已知模型/平台、实测依据、媒体是否齐备与核查日期。未知字段不展示占位推断。
5. 关联笔记预览与制作链路。笔记卡提供标题、一段用途摘要、目录片段，进入独立笔记页；只有确实对应独立图像/视频提示词的内容才进入制作链路。

### 笔记页

- 采用暖白背景、窄于案例媒体的正文栏。桌面端可有目录侧栏，手机端目录收在正文前部。
- 表格允许在局部横向滚动；代码块与提示词块保持原有缩进和换行；Wiki 内链转成有效站内链接。
- 关联案例放在正文末尾或侧栏，不打断阅读主线。

## 5. 图标规范

- 采用统一的线性图标；基准 `20px`，紧凑控件可用 `16px`；描边约 `1.75px`，端点和转角保持一致。
- 核心图标：搜索、图像、视频/播放、复制、已复制、笔记/书页、箭头、筛选、关闭、外链。避免为每个题材制作风格各异的图标。
- 图标服务于文字，不代替文字。“复制全文”“实测成片”“参考图”“阅读笔记”必须保留可见标签。提示词和媒体状态不能只用符号判断。
- 同一动作全站使用相同图标与文案。箭头用于导航，复制图标用于复制，播放图标仅用于视频，不用无关装饰符号。
- 采用可维护的图标资源或 SVG。不要混用 Emoji、系统字形和多套不同风格图标。

## 6. 交互与反馈

| 场景 | 预期行为 |
| --- | --- |
| 复制全文 | 按钮默认“复制全文”；成功后在按钮附近显示勾选图标和“已复制完整提示词”，约 3 秒后恢复。复制 payload 只含源提示词原文。失败时显示“复制失败，请手动选取”，并保留可选择的正文。 |
| 复制本段 | 仅在多段确实有独立复用价值时出现；按钮文案明确为“复制本段”，成功反馈同位置显示段落名称。 |
| 媒体切换 | 使用带文字的下划线标签，例如“实测成片”“参考图”“人物设定”。默认项由真实媒体角色决定；切换后标题、说明与媒体同步变化。视频不自动播放。 |
| 图片查看 | 详情媒体保持完整画幅；点击可放大，支持关闭按钮和键盘关闭。缩略图裁切不得成为唯一可见版本。 |
| 笔记预览 | 案例页展示摘要及目录片段；点击进入完整笔记阅读页。不要用小弹窗承载整篇长笔记。 |
| 搜索和筛选 | 输入后更新结果数；已选条件有文字与明显状态；支持清空搜索、清除全部筛选。搜索结果卡仍标明媒介及媒体身份。 |
| 空态/加载/失败 | 明确告知“暂无结果图/暂无成片”“没有匹配案例”“媒体加载失败”，并给出可行操作；不能用装饰图假装真实结果。 |

所有可操作控件均有可见的键盘焦点。媒体切换可以用语义化 tab 模式或同等可访问的按钮组实现，并保证键盘可达与选中状态可读。点击区域至少约 `44 × 44px`；视觉图标可小于点击区域。动画只用于轻微的悬停与反馈，时长约 `150–220ms`，不添加自动轮播、强制视差或自动播放。

## 7. 响应式规则

- `≥1200px`：首页及列表容器约 `1200px`，案例卡三列；单案例仍保持大幅媒体后接阅读区，不改为媒体与提示词并列。
- `768–1199px`：列表两列；导航和搜索可收紧，但主要入口保留文字。
- `<768px`：列表一列；案例严格按“主题 → 媒体 → 提示词 → 来源 → 笔记”排列。媒体附件标签横向滚动或换行，不能截断重要身份文字。
- 手机端提示词正文不缩到小字；长英文串或代码允许在阅读容器内换行/局部滚动，页面整体不出现横向溢出。
- 实现 Agent 应以桌面约 `1440px`、平板约 `768px`、手机约 `390px` 的真实浏览器视口复核首页、四类案例页和长笔记页。验收看实际渲染、文本可读性、媒体比例、焦点与复制反馈。
